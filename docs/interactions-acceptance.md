# 交互功能逐项验收

验收程序：`examples/interactions`。它提供七个分类页面，每个可发送的测试项都有入口按钮、
演示按钮/文本及后端处理器。没有只展示名称、不处理点击的占位按钮。

## 启动

```powershell
$env:GOTOOLCHAIN = "go1.24.4"
go run ./examples/interactions -config config.yaml
```

单聊发送 `/interact`，群聊发送 `@机器人 /interact`。
目录包括“基础按钮、高级按钮、按钮权限、六种响应码、文本交互、平台原生事件、普通消息”。

WebSocket 的 intents 需要 `GROUP_AND_C2C_EVENT` 和 `INTERACTION`。
测试频道时再按实际权限加入 `PUBLIC_GUILD_MESSAGES`；频道私信需要 `DIRECT_MESSAGE`。
不要将客户端/平台未开放的能力记作通过。

平台资源需使用当前机器人的真实值，可选参数如下：

```powershell
go run ./examples/interactions -config config.yaml `
  -keyboard-template "你的键盘模板ID" `
  -miniapp-url "真实小程序跳转链接" `
  -role-id "当前频道角色ID" `
  -channel-id "当前频道内的目标子频道ID" `
  -menu-feature "平台配置的快捷菜单feature_id"
```

未配置资源时，点击相应测试项会明确显示“未配置/仅对应场景可测”，不会伪造成功。
模板的指令动作建议设置为 `/itest template`；模板回调由通用 type=11 处理器接收并响应。

## 可点击用例与处理结果

| 分类 | 测试项 | 对应处理/核对结果 |
| --- | --- | --- |
| 基础按钮 | 普通回调 | ACK 0，然后回复处理结果 |
| 基础按钮 | 命令预填 | 预填 `/itest prefill 参数`，手动发送后显示收到的参数 |
| 基础按钮 | 自动发送 | 单聊自动发 `/itest auto`；群聊/频道预填后手动发送，均有命令处理器 |
| 基础按钮 | 引用命令 | `/itest quote` 有处理结果，是否出现引用需核对客户端 |
| 基础按钮 | 网页跳转 | 打开官方文档；返回后点“我已核对效果”确认 |
| 基础按钮 | 点击后文字 | 独立回调处理，核对“点击测试”是否变为“已点击” |
| 基础按钮 | 四种样式 | 0、1、3、4 各有按钮及专用回调处理器 |
| 基础按钮 | 低版本提示 | 高版本正常执行命令；低版本是否展示 unsupport_tips 需使用对应客户端核对 |
| 基础按钮 | 纯文本按钮 | 发送 text+keyboard，按钮有专用回调；实际展示需核对平台/客户端 |
| 高级按钮 | 二次确认 | 取消不应产生回调；确认后 ACK 并显示结果 |
| 高级按钮 | 互斥分组 | A/B 各有回调，选择后核对同组另一按钮是否变灰 |
| 高级按钮 | 单聊选图 | 支持的手机单聊客户端打开选图器；收到命令后显示附件数量，0 个不算图片接收通过 |
| 高级按钮 | 选择子频道 | 频道选择后发送到所选子频道；其他场景预填，对应命令均有处理 |
| 高级按钮 | 旧点击次数 | 每次实际回调都处理；click_limit 已弃用，不承诺平台会限次 |
| 高级按钮 | 模板键盘 | 使用真实模板；模板指令和回调都有处理入口 |
| 高级按钮 | 小程序跳转 | 使用真实链接；返回后手动确认，后台不能伪造跳转事件 |
| 高级按钮 | 严格模式 | 单聊发送严格 AutoSend 示例；群聊/频道显示预期的本地校验拒绝结果 |
| 按钮权限 | 所有人、指定用户、管理员、频道角色 | 都有专用回调；需不同测试账号验证允许和拒绝，拒绝本来就不会产生业务回调 |
| 普通消息 | 普通文字、附件消息、未知命令 | 分别由 OnMessage 接收并给出可见回复，空正文附件也处理 |
| 六种响应码 | 0～5 各一个按钮 | 分别发送对应 ACK，并回复实际发送的 code；非零码是刻意的错误反馈测试 |
| 文本交互 | 提及自己 | 群聊/频道发送对应 @标签；单聊显示不支持 |
| 文本交互 | 全体文本、全体MD | 带管理员权限及二次确认的入口；发送后核对标签展示 |
| 文本交互 | 文本预填 | 原文 `/itest input 中文 + &`，核对 URL 编码、引用和收到的参数 |
| 文本交互 | 文本发送 | 单聊点击发送 `/itest enter`；群聊/频道回退为预填，发送后有处理结果 |
| 文本交互 | 频道跳转 | 使用同一频道真实子频道 ID；返回后手动确认 |
| 文本交互 | 频道系统表情 | 发送系统 emoji 标签并展示普通 Unicode 对照，手动核对 |

@全体成员在群聊受“机器人需为管理员、每群每天一次”限制，不能在同一群同一天把文本和 MD 两种
发送都记作成功。请使用不同测试群或跨天测试；平台拒绝时程序会显示错误码和“本项未通过”。
任何已知平台 API 拒绝都会尝试发送独立的失败说明；网络中断或回复来源过期时可能无法继续发送反馈，
此时终端记录错误，不能算通过。

## 平台原生事件

消息反馈（13）、清空会话（14）、故事（15）、模型切换（16）、用户授权（18）、群授权（19）、
群授权状态变化（20）必须由相应的 QQ 原生 UI/平台能力产生；普通消息按钮不能伪造成这些事件。
快捷菜单（12）也需要在平台配置后从原生菜单点击。

这些事件都注册了真实处理器：

- 11/12 调用 ACK，并给出消息反馈；外部模板按钮也可由通用 type=11 处理器接收。
- 13/14/15/16/18/19/20 记录接收次数，不发送不必要的 ACK。
- 在“平台原生事件”页点击“刷新事件记录”查看次数。目录专用按钮不计入该原生事件报告。
- 类型 14 的测试程序不清除业务数据库，也不会假装操作了并不存在的聊天历史。

未开放的原生 UI 能力显示为未测试，不能通过本地模拟冒充客户端联调通过。

## 自动化测试实际做了什么

```powershell
go test ./examples/interactions -v
```

测试执行示例自身的菜单生成和 handler 注册，并使用真实 SDK Router/API 客户端、模拟 HTTP 平台：

1. 从 `/interact` 开始，递归读取实际发送 JSON 中的全部按钮和文本命令标签。
2. 针对每个回调 ID 派发对应互动，检查进入专用处理器、先 ACK 后回复、正确响应码及正确来源 ID。
3. 将每个指令按钮/文本标签产生的命令送入真实命令路由，检查有对应回复。
4. 在 C2C、群聊、频道三种场景分别遍历，检查 AutoSend、选图、频道选择器的适配结果。
5. 检查四种样式、全部权限类型、模板、跳转按钮，并确保客户端跳转有配套手动核对入口。
6. 对所有已列举原生事件输入模拟事件，检查处理器、ACK 规则及事件报告。
7. 模拟平台拒绝 @全体，验证能返回明确失败说明，而非沉默或报成功。

这证明请求、路由和处理闭环通过；不能证明真实 QQ 客户端渲染、权限拦截、跳转或手机选图已通过。
真实点击验收仍需在 QQ 客户端逐项进行。本程序不会给所有条目自动标记 PASS。
